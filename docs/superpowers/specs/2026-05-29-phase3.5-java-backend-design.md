# Phase 3.5：Java 后端引入 — Strangler Fig 渐进式迁移

## 目标

引入 Java Spring Boot，采用 **Strangler Fig（绞杀者模式）** 渐进式接管业务。不是一刀切重写，而是让 Java 逐步包围 Python，最终形成 **Java（控制面）+ Python（Agent 引擎）** 的双语言微服务架构。

## 核心原则

1. **增量引入，不碰老代码** — Java 先接新业务（商品管理等），Python 保留 Agent 核心
2. **网关层平滑切流** — Traefik 精细分流，按路径决定请求去 Java 还是 Python
3. **双向异步通信** — 复用 RabbitMQ（Phase 2 成果），Java 和 Python 通过消息队列协作

## 三大工程挑战的解决方案

### A. 数据库控制权交接（DB Ownership）

**原则：Java (Flyway) 成为 PostgreSQL 的唯一 Schema 管理者。**

| 操作 | 负责方 | 说明 |
|------|--------|------|
| DDL（CREATE/ALTER/DROP） | **Flyway（Java）** | 唯一的 schema 变更入口 |
| DML（SELECT/INSERT/UPDATE） | Java + Python | 双方都能读写数据 |
| Alembic | **删除** | Python 端不再需要迁移脚本 |

**交接步骤**：
1. 将现有 Alembic 迁移脚本转化为 Flyway 迁移脚本（SQL 格式）
2. Flyway V1 脚本 = 创建所有现有表（users, api_keys, products, orders, ...）
3. 删除 `alembic/` 目录和 `scripts/migrate.py`
4. Python 的 SQLModel 保留（用于 ORM 读写），但不再负责 DDL
5. Docker entrypoint 改为 `alembic upgrade head` → Java 启动时 Flyway 自动迁移

**好处**：schema 版本单一来源，不会出现两边改表冲突的灾难。

### B. 鉴权状态跨语言信任（Auth Handoff）

**方案：非对称加密 — RSA 私钥签名 + JWKS 公钥验证**

这是企业级微服务安全的标准实践，也是面试高级亮点。

```
┌─────────────┐    sign (RSA private key)    ┌─────────────┐
│  Java        │ ──────────────────────────▶ │  JWT Token   │
│  Spring Boot │                              │  (RS256)     │
└─────────────┘                              └──────┬──────┘
                                                    │
                         ┌──────────────────────────┤
                         │                          │
                         ▼                          ▼
              ┌──────────────────┐        ┌──────────────────┐
              │  Java JWKS 端点   │        │  Python           │
              │  /.well-known/   │        │  PyJWT 验证       │
              │  jwks.json       │◀───────│  (拉取公钥)       │
              └──────────────────┘        └──────────────────┘
```

**实现细节**：
- Java 启动时生成 RSA 密钥对（或从环境变量加载），私钥签名 JWT
- Java 暴露 `GET /.well-known/jwks.json` 端点，返回公钥的 JWK 格式
- Python 启动时调用 JWKS 端点拉取公钥，缓存到内存
- Python 用 PyJWT + RSA 公钥验证 JWT（`jwt.decode(token, public_key, algorithms=["RS256"])`）
- **密钥轮换**：JWKS 支持多个 key（`kid` 字段），可无缝轮换

**Token payload 保持一致**（与现有 Python JWT 兼容）：
```json
{
  "sub": "user_id",
  "tenant_id": "tenant_id",
  "type": "access",
  "exp": 1234567890,
  "iat": 1234567800,
  "iss": "shopmesh-java"
}
```

### C. Traefik 路由分流

**原则：Traefik 直接分流，不走 Java 代理 Python。**

```yaml
# traefik/dynamic.yml — 路由规则
http:
  routers:
    # Java 路由：Auth / API Key / Merchant / Products
    java-api:
      rule: "PathPrefix(`/api/auth`) || PathPrefix(`/api/users`) || PathPrefix(`/api/merchants`) || PathPrefix(`/api/products`)"
      entryPoints: ["web"]
      service: java-service
      middlewares: ["gateway-ratelimit@file", "security-headers@file"]

    # Python 路由：Agent 聊天 / 会话 / 行为
    python-agent:
      rule: "PathPrefix(`/api/chat`) || PathPrefix(`/api/conversations`) || PathPrefix(`/api/behavior`) || PathPrefix(`/api/tasks`)"
      entryPoints: ["web"]
      service: python-service
      middlewares: ["gateway-ratelimit@file", "security-headers@file"]

    # JWKS 端点（无需认证）
    jwks:
      rule: "Path(`/.well-known/jwks.json`)"
      entryPoints: ["web"]
      service: java-service

  services:
    java-service:
      loadBalancer:
        servers:
          - url: "http://java-api:8080"

    python-service:
      loadBalancer:
        servers:
          - url: "http://python-agent:9000"
```

**好处**：
- Agent 聊天请求直接到 Python，不经过 Java 代理，减少延迟
- 每个服务独立扩缩容
- 职责清晰，故障隔离

## Strangler Fig 渐进式迁移策略

### 阶段 1：增量引入（Phase 3.5）

Java 先接管 **Auth + API Key + Merchant CRUD**。Python Agent 保持不变。

```
/api/auth/*          → Java（新增）
/api/auth/api-keys/* → Java（新增）
/api/chat/*          → Python（保持不变）
/api/conversations/* → Python（保持不变）
```

**Python auth 模块状态**：保留代码但不注册路由（`app.include_router(auth_router)` 注释掉），作为 fallback。

### 阶段 2：平滑切流（Phase 3.5 后期）

Java Auth 测试通过后，Traefik 将 `/api/auth` 流量从 Python 切到 Java。

**验证清单**：
- [ ] 注册 → 返回 JWT → 用 JWT 访问 Python Agent → 正常工作
- [ ] API Key → 用 X-API-Key 访问 Python Agent → 正常工作
- [ ] 刷新 token → 新 token → 正常工作

### 阶段 3：双向异步通信（Phase 3.5 后期）

复用 RabbitMQ（Phase 2 成果），Java 和 Python 通过消息队列协作：

| 事件 | 发布方 | 消费方 | 说明 |
|------|--------|--------|------|
| `user.registered` | Java | Python | 初始化用户向量记忆 |
| `user.profile.updated` | Java | Python | 更新 Qdrant 中的用户偏好 |
| `api_key.created` | Java | Python | 同步 API Key 状态（可选） |
| `agent.recommendation` | Python | Java | 推荐结果存入 Java 管理的统计表 |

**Python Celery 新增 Consumer**：

**Flyway 唯一管理 Schema**


**Python SQLModel 保留**（只做 ORM 映射，不负责 DDL）：
- `User`, `ApiKey` → Java JPA 实体（primary）
- `Product`, `UserProfile`, `SessionRecord`, `Order`, `ConversationMessage` → Python SQLModel（read/write）

## 任务分解

### P3.5-T1：Spring Boot 项目骨架
- Spring Initializr 初始化（spring-boot-starter-web, security, data-jpa, amqp）

- Dockerfile + Docker Compose 集成
- 验证：`docker compose up` → Java 启动 → Flyway 自动建表 → `/api/health` 返回 OK

### P3.5-T2：RSA JWT + JWKS
- JwtProvider：RSA 密钥对生成/加载，RS256 签名
- `GET /.well-known/jwks.json`：暴露公钥（JWK 格式）
- JwtAuthFilter：Spring Security JWT 验证过滤器
- AuthController：register / login / refresh / me
- SecurityConfig：公开端点配置（auth/*, health, jwks）
- 测试：注册 → 获取 JWT → 访问 /me → 正常

### P3.5-T3：API Key + 用户模块
- User JPA Entity（映射 users 表）
- ApiKey JPA Entity + Repository
- ApiKeyController：create / list / revoke
- 测试：JWT 认证 → 创建 API Key → 用 API Key 访问 /me

### P3.5-T4：Python 端 JWT 验证改造
- Python 新增 JWKS 客户端：启动时拉取公钥，缓存 + 定期刷新
- `src/auth/jwks_client.py`：`fetch_public_key()` → `jwt.decode(token, key, algorithms=["RS256"])`
- 删除 Python 的 JWT 签发逻辑（不再生成 token）
- 保留 `decode_token()` 但改为用 RSA 公钥验证
- 删除 Alembic（Flyway 接管）
- 测试：Java 签发的 token → Python 能验证

### P3.5-T5：Traefik 路由分流
- 更新 `traefik/dynamic.yml`：Java 路由 + Python 路由
- 移除 Python 端 auth 路由注册（`app.include_router(auth_router)` 注释）
- Python 端口改为 9000
- 验证：`/api/auth/login` → Java；`/api/chat` → Python

### P3.5-T6：RabbitMQ 异步通信
- Java 端：`UserEventPublisher`（注册/偏好变更时发消息）
- Python 端：Celery consumer 监听 `events` 队列
- 新增 `src/tasks/event_tasks.py`：处理 user.registered / user.profile.updated
- 端到端验证：Java 注册用户 → RabbitMQ → Python 初始化记忆

### P3.5-T7：测试 + 文档

## 附录：与原 spec 的变更对比

| 维度 | 原方案 | 新方案 |
|------|--------|--------|
| DB 管理 | Flyway + Alembic 共存 | **Flyway 唯一**，删除 Alembic |
| JWT | HS256 共用 secret | **RS256 非对称 + JWKS** |
| Traefik 路由 | 全部 → Java → 代理 Python | **精确分流**，直接到各服务 |
| Agent 请求路径 | Client → Java → Python（多一跳） | **Client → Traefik → Python**（直达） |
| 迁移策略 | 一步到位 | **Strangler Fig**，渐进式 |
| 跨语言通信 | 仅 HTTP 同步 | **RabbitMQ 异步**（复用 Phase 2） |
