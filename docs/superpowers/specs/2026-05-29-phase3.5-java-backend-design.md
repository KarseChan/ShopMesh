# Phase 3.5：Java 后端引入 — CRUD/鉴权迁移

## 目标

引入 Java Spring Boot 作为 **API 网关 + CRUD 服务**，Python 保留作为 **Agent 执行引擎**。形成 Java（控制面）+ Python（数据面）的双语言架构。

## 为什么

1. **简历价值**：Python 全栈 → Java + Python 双语言，覆盖企业级技术栈
2. **架构合理性**：CRUD/鉴权/网关是 Spring Boot 的强项；LangGraph/向量检索是 Python 的强项
3. **Phase 3.5 定位**：为 Phase 5（RBAC/安全体系）和 Phase 7（支付/商家后台）打 Java 基础

**流量路径**：
- **认证/CRUD 请求**：Client → Traefik → Java → PostgreSQL
- **Agent 聊天请求**：Client → Traefik → Java（鉴权）→ Python（Agent 执行）→ Java（响应）
- **Agent 内部调用**：Python 直接读写 PostgreSQL / Redis / Qdrant（不经 Java）

## 职责划分

### Java 控制面（新增）

| 模块 | 说明 |
|------|------|
| Auth | 注册/登录/刷新/me（JWT 生成验证） |
| API Key 管理 | 生成/列表/吊销 |
| Merchant CRUD | 商品管理、Agent 配置（Phase 7 扩展） |
| 任务状态代理 | `GET /api/tasks/{task_id}` 代理到 Celery（Redis 查询） |
| 健康检查 | `GET /api/health` |
| Agent 代理 | `POST /api/chat` → 转发到 Python Agent 服务 |

### Python 数据面（保留 + 瘦身）

| 模块 | 说明 |
|------|------|
| LangGraph Agent | 多 Agent 编排、ReAct 循环 |
| Tools | product_search, review_summary 等 |
| Memory | 向量记忆、用户画像 |
| Celery Tasks | 异步任务（记忆压缩、画像更新） |
| Vector Search | Qdrant 检索 |

**Python 移除**：Auth 模块（JWT、API Key）、CRUD 路由、TenantMiddleware（由 Java 处理）

## API 设计

### Java 端口：8080（对外）

```
POST   /api/auth/register       — 注册
POST   /api/auth/login           — 登录
POST   /api/auth/refresh         — 刷新 token
GET    /api/auth/me              — 当前用户信息

POST   /api/auth/api-keys        — 创建 API Key
GET    /api/auth/api-keys        — 列表 API Key
DELETE /api/auth/api-keys/{id}   — 吊销 API Key

POST   /api/chat                 — 聊天（代理到 Python）
POST   /api/chat/order           — 下单（代理到 Python）
POST   /api/chat/resume          — 恢复（代理到 Python）
GET    /api/tasks/{task_id}      — 任务状态
GET    /api/conversations        — 会话列表（代理到 Python）
GET    /api/health               — 健康检查
```

### Python 端口：9000（内部，不对外暴露）

```
POST   /internal/chat            — Agent 聊天（仅接受 Java 转发）
POST   /internal/chat/order      — Agent 下单
POST   /internal/chat/resume     — Agent 恢复
GET    /internal/conversations   — 会话列表
POST   /internal/behavior        — 行为上报
GET    /internal/health          — 健康检查
```

**内部通信**：Java → Python 通过 HTTP（WebClient），请求头携带 `X-Tenant-ID` 和 `X-User-ID`（由 Java 从 JWT 解析后注入）。

## 数据库共享策略

**共享同一个 PostgreSQL 实例**，但按表划分所有权：

| 表 | Owner | 说明 |
|----|-------|------|
| `users` | Java | JPA 实体 |
| `api_keys` | Java | JPA 实体 |
| `products` | Java（Phase 7） | 暂时 Python 继续用 |
| `user_profiles` | Python | SQLModel |
| `sessions` | Python | SQLModel |
| `orders` | Python | SQLModel |
| `conversation_messages` | Python | SQLModel |
| `intent_samples` | Python | SQLModel |

**迁移工具**：
- Java 侧：Flyway（管理 Java owned 表）
- Python 侧：Alembic（继续管理 Python owned 表）
- 初始策略：Flyway 不碰 Python 的表，Alembic 不碰 Java 的表

**注意**：初始阶段 Java 复用已有的 `users` 和 `api_keys` 表（由 Alembic 创建），Flyway 只管理增量迁移。后续 Phase 逐步将表 ownership 迁移到 Flyway。

## JWT 兼容性

Java 和 Python 共用同一个 JWT secret（从环境变量 `JWT_SECRET_KEY` 读取），算法 HS256。这样：
- Java 生成的 token → Python 能验证（双向兼容）
- 现有前端不需要改动

**token payload 保持一致**：`sub`, `tenant_id`, `type`, `exp`

## Docker Compose 变更

```yaml
# 新增 Java 服务
java-api:
  build: ./shopmesh-java
  ports:
    - "8080:8080"
  environment:
    JWT_SECRET_KEY: ${JWT_SECRET_KEY}
    DATABASE_URL: postgresql://postgres:password@postgres:5432/shopping_agent
    PYTHON_AGENT_URL: http://python-agent:9000
  depends_on:
    postgres:
      condition: service_healthy
    python-agent:
      condition: service_healthy

# Python 服务改名，端口改为 9000（不对外暴露）
python-agent:
  build: .
  expose:
    - "9000"
  environment:
    DATABASE_URL: postgresql://postgres:password@postgres:5432/shopping_agent
    REDIS_URL: redis://redis:6379
    QDRANT_URL: http://qdrant:6333
    CELERY_BROKER_URL: amqp://guest:guest@rabbitmq:5672//
    # 不再需要 JWT 相关配置

# Traefik 路由改为指向 Java
# labels:
#   - "traefik.http.routers.app.rule=PathPrefix(`/api`)"
#   - "traefik.http.services.app.loadbalancer.server.port=8080"  # 改为 Java 端口
```

## 任务分解

### P3.5-T1：Spring Boot 项目骨架
- 初始化 Spring Boot 项目（Spring Initializr）
- 配置 PostgreSQL + JPA
- 基础 health check
- Dockerfile + Docker Compose 集成

### P3.5-T2：JWT 认证迁移
- JwtProvider：token 生成/验证（与 Python 共用 secret）
- AuthController：register/login/refresh/me
- Spring Security filter chain
- 测试

### P3.5-T3：API Key + 用户模块
- ApiKey JPA Entity + Repository
- ApiKeyController：CRUD 端点
- UserRepository（复用 users 表）
- 测试

### P3.5-T4：Agent 代理层
- ChatController：接收前端请求，转发到 Python Agent
- WebClient 配置（连接池、超时、重试）
- SSE 透传（StreamingResponse 转发）
- 请求头注入（X-Tenant-ID, X-User-ID）

### P3.5-T5：Python 瘦身
- Python auth 模块移除（或保留为内部 fallback）
- Python 端口改为 9000
- 新增 `/internal/*` 路由（仅接受 Java 转发）
- Traefik 路由指向 Java

### P3.5-T6：测试 + 文档
- Java 侧集成测试（Testcontainers）
- 端到端测试（Client → Java → Python）
- 更新 README 和进度文档

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| Java 学习曲线 | Spring Boot 约定优于配置，Claude 辅助 |
| 双语言维护成本 | 清晰的职责边界，Java 只做 CRUD |
| JWT 兼容性问题 | 共用 secret + 相同 payload 结构 |
| 数据库迁移冲突 | 按表划分 ownership，不互相干扰 |
| SSE 透传复杂性 | WebClient 支持 SSE，逐行转发 |

## 简历技术点

- Java Spring Boot + Python 双语言微服务架构
- Spring Security + JWT 认证鉴权体系
- Spring Data JPA + Flyway 数据库管理
- WebClient 异步通信 + SSE 透传
- 双语言 JWT 共用（token 互认）
- Docker Compose 多服务编排
